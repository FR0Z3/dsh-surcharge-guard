# dsh-surcharge-guard

给每个模型设置“双倍计费起点”，在请求跨过这条线之前压缩上下文。适用于 GPT、Gemini、Grok 这类长上下文、但超过固定阈值后按双倍计费的模型。

## 为什么不能调上下文窗口

DSH 用这个公式决定何时压缩：

```
T = min(W × thresholdRatio, W − output − headroom)
```

`W` 是上下文窗口。第一项是 `W` 的比例，所以**窗口调小，触发点跟着往下掉**。对一个 272K 以上双倍计费的模型：

| `W` | 输出预留 | headroom | 触发点 `T` |
|---:|---:|---:|---:|
| 1,050,000 | 128,000 | 65,536 | 840,000 |
| 272,000 | 128,000 | 65,536 | **78,464** |
| 272,000 | 32,000 | 22,400 | 217,600（上限） |

把窗口设成 272K 不会在 272K 触发，而是在 78K 触发，因为 `W − output − headroom` 先塌了。而 `W × 0.8` 把触发点锁死在 217,600，272K 的窗口永远贴不到 272K。

这个插件直接把阈值写进去，反解需要多少 headroom：

```
headroom = W − output − (起点 − 安全余量)
```

窗口容量保持原样，只改触发位置。

## 用法

安装后打开 **插件 → 计费保护**，配置就在插件页里：

1. 打开总开关。
2. 点「添加全部 GPT 模型」「添加全部 Gemini 模型」等按钮，一次为所有服务商下的匹配模型建规则。
3. 表格里逐条核对起点，需要时直接改数字。表里还有一列「到线前触发于」，显示反解出来的实际压缩点。

| 目标 | 操作 |
|---|---|
| 只保护某几个模型 | 批量添加后，把不需要的行点「已停用」或「移除」 |
| 改某个模型的阈值 | 表格「双倍计费起点」列直接改 |
| 削减压缩频率 | 加大「安全余量」 |
| 整轮临时关掉 | 关总开关，规则保留 |

数字框接受 `272000`、`272K`、`1.05M` 三种写法。

## 配置项

| 字段 | 默认值 | 说明 |
|---|---|---|
| `enabled` | `true` | 总开关，关掉后所有规则停止生效 |
| `rules` | `[]` | 每条形如 `{ provider, model, surchargeAtTokens, enabled }` |
| `safetyMarginTokens` | `20000` | 在起点以下多少 token 触发 |
| `retainRatio` | `0.16` | 压缩时保留最近多少比例不摘要 |
| `maxAttempts` | `2` | 同一轮内摘要的最大尝试次数 |

全部字段是 volatile 的，改完当步生效，不重启插件。

## 内置阈值

| 家族 | 起点 | 匹配方式 |
|---|---:|---|
| GPT | 272K | 模型 id 里 `gpt` 出现在词首 |
| Gemini | 200K | 模型 id 含 `gemini` |
| Grok | 200K | 模型 id 含 `grok` |

阈值是 provider 公布的数字，不是从窗口算出来的。厂商改价时直接改表格里的数。

## 限制

- **压缩本身要花 token。** 每次折叠都会发一次摘要请求。阈值设得太低、轮次又长时，摘要成本可能超过省下的钱，这时该加大安全余量或关掉部分模型。
- **只在步与步之间检查。** 单步里追加了很大的工具结果时，仍可能在下次检查前越线。安全余量覆盖的是常规增长，不是一次巨额追加。
- **摘要可能不肯变小。** 内容已经很密时，摘要返回的文本可能不比原文短。`maxAttempts` 用来避免它在同一轮里反复重试。

## 工作方式

每一步开始前，插件读这一步路由到的模型。命中规则且用量进入安全余量范围时，选一段工具配对完整的区间，交给会话自己的 compaction 服务折成一条摘要。

插件不写新的 session 事件类型，也不替换任何服务。唯一的持久写入是 `compaction/start` .. `compaction/end` 这一对，由 `compactRegion` 自己负责，所以 fork、resume、replay 与不装插件时完全一致。

截止的区间会退到最近的工具配对平衡点，开头的 system 消息永远不进区间。

## 开发

```
pnpm install
pnpm check          # 语法 + 本地化一致性 + 全部测试
pnpm test           # 只跑测试
```

- `logic.js` 是不依赖任何运行时的纯函数模块，`tests/logic.test.mjs` 直接测它。
- `tests/client.test.mjs` 用 `react-test-renderer` 加桩 `fetch` 挂载设置页，检查表格、批量添加、提交时机和失败态。
- `index.js` 是 Host 半边：注册 `agent/pre-step`，并提供三个同源路由给设置页读写。
- `client.js` 是浏览器半边，注册到 `plugins.bundle.config`（按包名键控），配置读写走 `configForms`，因此不经过任何 HTTP 路由。
- `locale/*.json` 是 Plugin Manager 读的显示文案；界面字符串在 `client.js` 里内联一份，`scripts/check-locale.mjs` 保证两份不漂移。
